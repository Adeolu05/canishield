# Which wallets can pay a TEX (`tex1…`) address

Community research by Cryppit ([X @CryppitHQ](https://x.com/CryppitHQ) · [github.com/cryppit](https://github.com/cryppit)), 19 Nov 2026.

**Question:** can the wallet send ZEC to a ZIP 320 TEX address (`tex1…`), such as a Binance ZEC deposit address or a THORChain ZEC inbound address?

**Method:** every row comes from reading the wallet's source code or its release notes, not from a real send. None of these results was confirmed by sending funds. Each source link is pinned to the commit on the default branch on 19 Nov 2026, and the cited lines were re-read that day. "Pays tex1" means the code accepts a `tex1` recipient and builds a payment to it. For a wallet that holds shielded funds, it also means the wallet makes the ZIP 320 two-step payment (shielded funds go to a fresh transparent address first, then to the TEX address). A transparent-only wallet pays the TEX address's P2PKH script directly, which is what ZIP 320 requires.

**Not covered:** closed-source wallets and exchanges. Wallets whose TEX support we could not determine are left out.

**Status marks:**

- ✅ the code pays a `tex1` address.
- ⚠ partly works, or not confirmed.
- ❌ rejects a `tex1` address. A ❌ row says whether the refusal is by design or has an open issue.

## Related

- ZIP 320 edge cases, decided by the ZIP 320 Owners and merged on 19 Nov 2026 (zcash/zips#1469):
  - an all-uppercase TEX address is valid; mixed case is not;
  - excess padding is invalid.
- Test vectors for wallet and exchange developers: https://github.com/cryppit/zcash-tex-vectors. The proposed `zip_0320_invalid` set is in zcash/zcash-test-vectors#139.
